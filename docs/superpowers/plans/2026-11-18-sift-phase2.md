# Sift phase 2 (skeleton) and phase 2b (schema map): implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: `superpowers:subagent-driven-development` (or `superpowers:executing-plans`). Steps use `- [ ]` checkboxes. Every test step follows `docs/practices/verifying-tests-can-fail.md` in MetalUI: write the test, watch it fail, apply the listed **mutation** to the finished code, and confirm the test goes red before you revert the mutation.

**Goal.**
- **Phase 2:** a runnable Sift window on macOS, Linux and Windows. It has saved connections, Postgres containers found through Docker or OrbStack, a schema tree in the sidebar, and a table detail (columns, keys, indexes and the first rows) over a read-only libpq session. A session that drops is reconnected.
- **Phase 2b:** a schema map with a deterministic layered layout, pan, zoom, a minimap, fly-to search, neighbour highlighting, opening a table from the map, level of detail and culling, and dragged positions remembered per database. It stays smooth at 500 tables and 1,000 links.

**Architecture.**
- The UI-free targets each have their own tests:
  - `SiftCore`: the model, secrets, persistence and the source protocol;
  - `SiftPG`: libpq and the catalog queries;
  - `SiftDocker`: HTTP/1.1 over a unix socket or a named pipe;
  - `SiftLayout`: the Sugiyama layout. It imports nothing.
- `SiftKit` holds all the UI on MetalUI and is tested with `MetalUITesting`.
- `Sift` is the thin executable.
- `SiftTestSupport` holds fakes, fixtures and the fixture Postgres. It is UI-free.

**Tech stack.**
- Swift 6.4 toolchain, `swift-tools-version: 6.1`, Swift 6 language mode.
- Swift Testing.
- libpq.
- MetalUI by local path `../MetalUI`, with the `SDL` and `AccessKit` traits on Linux and Windows.

## 0. Ground rules for every lane

- **Tests count work, never time** (MetalUI `docs/testing.md`, "Warm frames").
  - A cost pin opens its window with `recordsLayout: false` and asserts `FrameWork` counters, or a component's static `bodyCount` (MetalFlow's `NodeCardView.bodyCount` pattern).
  - **Every cost pin first asserts its precondition is not vacuous**: so many cards are visible, so many edges are drawn, the row is really hovered.
- **The `SIFT_PG_URL` gate:** integration tests use `.enabled(if: PGFixture.url != nil, "SIFT_PG_URL is not set")`, as phase 0 does.
- **Runs:** `swift test --no-parallel` locally and in CI. MetalUI's own headless jobs need it: `Animation.parkedTransaction` is process-global. UI tests are `@MainActor`.
- **Local build on macOS:** `PKG_CONFIG_PATH=$(brew --prefix libpq)/lib/pkgconfig swift build`. Integration tests need `SIFT_PG_URL=postgresql://postgres@127.0.0.1:55432/postgres` or your own server.
- **Commits:** imperative subjects in the repository's style ("Add the libpq wrapper, value model and probe"), one per task, one branch per lane: `phase2/docker`, `phase2/introspection`, `phase2/skeleton`, `phase2b/layout`, `phase2b/map`.
- **No secret in any output:** a password is never in a log, `print`, error message, JSON file, accessibility label or test failure message. Tests that hold a password use `"s3cret"` and assert that it is absent.

## 1. Decisions

| # | Decision | Why |
|---|---|---|
| D1 | CI checks out Sift and MetalUI **side by side** (`$GITHUB_WORKSPACE/Sift`, `$GITHUB_WORKSPACE/MetalUI`) with `actions/checkout`. MetalUI is pinned by `env.METALUI_REF` (a SHA) at the top of `ci.yml`. A PR that needs a MetalUI fix bumps it. | Keeps `path: "../MetalUI"` as Alloy and MetalFlow have it. Neither Alloy nor MetalFlow has CI that builds MetalUI, so Sift is the first. A pinned ref keeps a MetalUI change from turning Sift red. |
| D2 | `metalUITraits` is `["SDL", "AccessKit"]` under `#if os(Linux) \|\| os(Windows)` and `[.defaults]` otherwise. Copied from the scaffold and Jotter. `MetalUIPortableText` and `MetalUISystemFonts` are listed **unconditionally** (SG-D). `MetalUISDL` is conditional on Linux and Windows. | `docs/getting-started.md` and `Examples/Jotter/Package.swift`. |
| D3 | `SiftKitTests` text: CoreText on macOS. On Linux and Windows, `PortableTextSystem` over `SystemFonts.resolver(directories: [<#filePath>/../../../MetalUI/Tests/Fonts])`, falling back to `SystemFonts.resolver()`. | The `swift:6.4-noble` container has no fonts, and `SystemFonts.resolver()` throws `NoFontsFound`. MetalUI's own tests read `Tests/Fonts` by `#filePath` (HT-J). This is deterministic and needs no apt step. |
| D4 | Linux CI builds **SDL 3.4.16 from source** (cached), installs it under `/usr` and runs `MetalUI/Backends/SDL/scripts/fetch-accesskit.py --prefix /usr`. Windows downloads `SDL3-devel-3.4.16-VC.zip` and uses `fetch-accesskit.py --print-flags`, as MetalUI's `sdl-gpu-linux.yml` does. **No test needs SDL.** `TestWindow` is headless, as MetalUI's root jobs show. SDL is needed only because `swift build --build-tests` builds the `Sift` executable. | Ubuntu 24.04 ships only SDL2. The importer ignores `CPATH`, and gold skips `/usr/local/lib` (PX-I). |
| D5 | **Read-only is enforced twice.** The startup option is `options=-c default_transaction_read_only=on`. After connecting, `SHOW default_transaction_read_only` must answer `on`. Otherwise Sift runs `SET default_transaction_read_only = on`, checks again, and refuses the session with `SourceError(.readOnlyNotEnforced)`. Phase 2 has no editing UI at all. | A pooler such as pgbouncer can drop startup options. |
| D6 | **Connect with `PQconnectdbParams`** (keyword and value arrays, `expand_dbname = 0`). Sift never builds a conninfo string from parts. | No quoting bugs, and no password inside a string that might be logged. |
| D7 | **Identity is by name, never by OID.** `RelationID(schema, name)` keys selection, map positions, card ids and FK navigation. The OID is kept only as information. | A recreated container gets new OIDs. Keying by name is what makes "reconnect is painless" true. |
| D8 | **Catalog queries never decode Postgres arrays.** Each multi-valued catalog field (`conkey`, `confkey`, `indkey`) is `unnest(...) WITH ORDINALITY` into rows. | Array text quoting is a bug farm. Order comes from `ordinality`. |
| D9 | **Docker endpoint order.** `DOCKER_HOST`, if set, is the **only** candidate. A `tcp://` or `ssh://` scheme is reported as unsupported. Otherwise the order is: the current context (`DOCKER_CONTEXT`, else `currentContext` in `$DOCKER_CONFIG/config.json` or `~/.docker/config.json`), then `~/.orbstack/run/docker.sock`, then `/var/run/docker.sock`, then `$XDG_RUNTIME_DIR/docker.sock`. On Windows: `\\.\pipe\docker_engine`. The first existing candidate wins. A context's endpoint is found by **scanning `contexts/meta/*/meta.json` for `"Name"`**. | Follows the design's order. Scanning avoids hashing the name with SHA-256, which would need a crypto dependency on Linux and Windows. |
| D10 | **Docker HTTP.** Unversioned paths (`/containers/json?all=1`, `/containers/{id}/json`). Every request sends `Connection: close` and the response is read to EOF. The parser handles `Content-Length` and `chunked`. Responses are capped at 16 MiB. Connect, read and write time out after 3 s by default. | Simplest correct HTTP/1.1 client. Docker and OrbStack answer with either framing. |
| D11 | **Container match.** A container is Postgres when its image repository's last path component contains `postgres`, `postgis`, `timescaledb` or `pgvector`, **or** it exposes or publishes `5432/tcp`. Only matching containers are inspected. Defaults follow the official image: user `POSTGRES_USER ?? "postgres"`, database `POSTGRES_DB ?? user`. `POSTGRES_PASSWORD_FILE` is reported and never read. `POSTGRES_HOST_AUTH_METHOD=trust` means no password. The host IP `0.0.0.0` or empty maps to `127.0.0.1`, and `::` to `::1`; IPv4 is preferred. **Flagged:** when the port is not published and the engine is OrbStack, Sift routes to the container's network IP on port 5432 (OrbStack exposes container IPs to the host). Otherwise the row says "5432 not published" and cannot connect. | Covers the user's OrbStack workflow. The OrbStack fallback is an assumption; check it on the user's machine. |
| D12 | **Secrets.** `Secret` is not `Codable`. Its `description`, `debugDescription` and `customMirror` are masked. `SavedConnection` has **no** password field. Passwords live in a `CredentialStore`. Version 1 ships `InMemoryCredentialStore` only. | The design's anti-goals. The OS stores are deferred (§12). |
| D13 | **App support directory** (pure `AppPaths`): `~/Library/Application Support/Sift` on macOS; `${XDG_DATA_HOME:-~/.local/share}/sift` on Linux; `%APPDATA%\Sift` on Windows. Writes are atomic (a temp file, then rename). A corrupt file is renamed `*.corrupt-N` and Sift starts empty. | Never lose a user's list by overwriting it. |
| D14 | **Reconnect.** On `connectionLost` the state becomes `.lost`. Retries come after 0.5, 1, 2 and 4 s, then every 5 s, through an injected `SiftClock`. Before each attempt on a container-backed session, discovery runs again, so a new port or password is used. On success the snapshot is reloaded and the selection is restored by `RelationID`. The user can "Reconnect now" or "Stop trying". | Covers a container being recreated. |
| D15 | **Minimum server version is Postgres 12.** Older servers get `SourceError(.other, "Postgres 12 or later is needed")`. A `reltuples < 0` estimate is `.unknown` (Postgres 14 and later). | `attgenerated` and `conparentid` exist from 11–12. |
| D16 | **The phase-2 preview** shows the first 100 rows and **the first 64 columns**, with a note "showing 64 of N columns". The view is a `ScrollView([.horizontal, .vertical])` over a `LazyVStack(pinnedViews: [.sectionHeaders])` of fixed-width cells. | The two-axis virtualised `Table` is phase 1 in MetalUI. This bounds the cost until then. |
| D17 | **Layout coordinates.** An FK edge runs from the referencing table to the referenced one, and `rank(to) > rank(from)`, so referenced tables sit to the right. Layering is longest-path. Cycles are broken by Eades–Lin–Smyth greedy with ties to the lowest id. Crossings are reduced by alternating barycenter sweeps, keeping the best order, with crossings counted by the Barth–Jünger–Mutzel accumulator tree. y is placed by alternating sweeps of **pool-adjacent-violators (isotonic) placement** toward the mean neighbour centre, so there is no overlap by construction. Components are laid out separately and shelf-packed, the largest first. **All internal iteration runs over sorted arrays, never over a `Dictionary` or `Set`.** | Deterministic, exact goldens can be derived by hand, and there are no overlaps. Swift's hash seeding varies per process. |
| D18 | **Map transform.** All cards and edges are placed in canvas units inside one container with `.scaleEffect(zoom, anchor: .topLeading).offset(pan)`. Pan and zoom then change only the outer effect, which takes the retained effect-replay path (RZ-A, RZ-B). The pan is snapped to whole device pixels, so path rasters hit the cache (PN-A, PN-E). | This deliberately differs from MetalFlow, which bakes zoom into card sizes and so rebuilds every card on a zoom. Its pan-as-offset idea is reused. |
| D19 | **Edges.** A cubic runs per route segment, subdivided (de Casteljau) until each piece fits in half a tile. Pieces are bucketed into **edge tiles** of `512 / zoomBucket` canvas units (`zoomBucket = 2^floor(log2 zoom)`). Each tile is one `.equatable()` `Path` component. The stroke width is `1.5 / zoomBucket`. | A raster extent of at most 512 points stays under the 2^20-pixel overscan limit, so a whole-pixel pan rasterizes 0 pixels. A zoom step re-rasterizes only the visible tiles (RZ-C). |
| D20 | **Highlighting uses a spotlight, not per-card dimming.** One scrim rectangle sits over the base layer, with copies of the neighbour cards and their edges above it (`.allowsHitTesting(false)`, `.accessibilityHidden(true)`). | A hover then costs O(degree) builds, not O(cards). |
| D21 | **Culling** uses a cull window of the viewport grown by 50% on each side. It is recomputed only when the viewport leaves the window's inner half. **Level of detail:** `full` at zoom ≥ 0.55, `compact` (name and row count) at 0.25 to 0.55, `nameOnly` below 0.25, with ±0.03 hysteresis. | Most pan and zoom steps change neither the culled set nor the level of detail, so no card rebuilds. |
| D22 | **Map positions** are stored per database identity: `saved:<uuid>:<db>` or `container:<containerName>:<db>`. The file is `<support>/map-positions/<fnv1a64(identity)>.json` and contains the identity and `{"schema.table": {x, y}}`. It is written on drag end, never per step. | Stable across container recreation (D7). |

## 3. Lanes and sequencing

```
2-B.1 core types (small PR) ──┬─> 2-A Docker ───────────┐
                              ├─> 2-B introspection ────┼─> 2-C skeleton UI ─> 2b-B map view
2b-A layout (independent) ────┴─────────────────────────┴───────────────────────^
```

- **2-B.1** is task B1 of the introspection lane, merged alone first, because 2-A and 2-C both need `Secret` and the schema model.
- **2-A, 2-B and 2b-A** run in parallel.
- **2-C** adds the MetalUI dependency and restructures CI.
- **2b-B** needs 2-C and 2b-A. Phase 1 (MetalUI `Table`) is not a prerequisite for any lane here.

## 5. Lane 2-A: Docker discovery (`phase2/docker`)

### Task A1: Endpoint resolver (pure)

- **Files:** create `Sources/SiftDocker/DockerEndpoint.swift` and `Tests/SiftDockerTests/EndpointResolverTests.swift`.
- **Interfaces:**
  ```swift
  public enum DockerEndpoint: Sendable, Equatable { case unixSocket(path: String), namedPipe(path: String) }
  public enum DockerEngine: Sendable, Equatable { case orbStack, dockerDesktop, other }   // from the socket path
  public struct DockerEndpointCandidate: Sendable, Equatable { public enum Source: Sendable, Equatable {
      case dockerHost, context(String), orbStack, system, rootless, windowsDefault }
      endpoint; source; var engine: DockerEngine }
  public struct DockerHostEnvironment: Sendable { variables: [String: String]; home: String; isWindows: Bool
      fileExists: @Sendable (String) -> Bool; readFile: @Sendable (String) -> [UInt8]?; listDirectory: @Sendable (String) -> [String]
      static var live: Self }
  public enum DockerEndpointResolver {
      public static func candidates(in: DockerHostEnvironment) throws(DockerError) -> [DockerEndpointCandidate]
      public static func resolve(in: DockerHostEnvironment) throws(DockerError) -> DockerEndpointCandidate }
  public enum DockerError: Error, Sendable, Equatable { case noEndpoint(tried: [String]), unsupportedScheme(String),
      socketPathTooLong(String), connectFailed(String), timedOut, http(status: Int, message: String),
      malformedResponse(String), decoding(String) }
  ```
- **Tests**, each over a fake environment:
  - `dockerHostIsTheOnlyCandidate`. `DOCKER_HOST=unix:///tmp/x.sock` gives `candidates == [.init(.unixSocket("/tmp/x.sock"), .dockerHost)]`.
    - Mutation: append the fallbacks.
  - `tcpDockerHostIsUnsupported`. Throws `.unsupportedScheme("tcp")`.
    - Mutation: treat tcp as unix.
  - `currentContextComesFromConfigAndMeta`. With `config.json {"currentContext":"orbstack"}` and `contexts/meta/abc/meta.json {"Name":"orbstack","Endpoints":{"docker":{"Host":"unix:///u/.orbstack/run/docker.sock"}}}`, `candidates[0].source == .context("orbstack")`.
    - Mutation: ignore `currentContext`.
  - `dockerContextEnvironmentWinsOverConfig`.
    - Mutation: read config first.
  - `dockerConfigEnvironmentMovesTheConfigDirectory`.
  - `defaultOrderWithoutAContext`. `candidates.map(path) == ["/h/.orbstack/run/docker.sock", "/var/run/docker.sock", "/run/user/501/docker.sock"]`.
    - Mutation: swap OrbStack and system.
  - `rootlessNeedsXDGRuntimeDir`. Without it, the count is 2.
  - `defaultContextIsSkipped`. `currentContext: "default"` gives a first source of `.orbStack`.
  - `windowsUsesTheEnginePipe`. Gives `[.namedPipe(#"\\.\pipe\docker_engine"#)]`, and `npipe:////./pipe/docker_engine` normalises to the same.
    - Mutation: leave the slashes as they are.
  - `resolvePicksTheFirstThatExists`. Only `/var/run/docker.sock` exists, so the source is `.system`.
  - `nothingExistsListsWhatWasTried`. Throws `.noEndpoint(tried:)` with 3 paths.
  - `socketPathTooLongIsReported`. A 120-byte path throws `.socketPathTooLong`; the limit is 104 on Darwin and 108 on Linux, including the NUL.
  - `engineFollowsThePath`. `.orbstack` gives `.orbStack`.
- **Commit:** "Resolve the Docker endpoint: DOCKER_HOST, context, OrbStack, system, rootless"

### Task A3: Byte streams, the fake daemon and `DockerClient`

- **Files:**

- **Interfaces:**
  ```swift
  public protocol ByteStream: AnyObject { func write(_ bytes: [UInt8]) throws(DockerError)
      func read(maxCount: Int) throws(DockerError) -> [UInt8] /* [] at EOF */; func close() }
  public final class UnixSocketStream: ByteStream { public init(path: String, timeoutSeconds: Double) throws(DockerError) } // SO_RCVTIMEO/SO_SNDTIMEO
  public final class NamedPipeStream: ByteStream { public init(path: String, timeoutSeconds: Double) throws(DockerError) } // WaitNamedPipeW + CreateFileW
  public struct DockerClient: Sendable { public init(endpoint: DockerEndpoint, timeoutSeconds: Double = 3,
      connect: (@Sendable (DockerEndpoint, Double) throws(DockerError) -> ByteStream)? = nil)
      public func get(_ path: String) throws(DockerError) -> HTTPResponse   // non-2xx → .http(status, message from {"message":…})
  }
  // SiftTestSupport
  ```

## 8. Lane 2b-A: layered layout (`phase2b/layout`)

All files are in `Sources/SiftLayout/` (imports nothing) and `Tests/SiftLayoutTests/`. With the default options, every node is 200×100, `layerGap` is 120 and `nodeGap` is 40.

**Public interface:**
```swift
public struct LayoutPoint: Sendable, Hashable { public var x, y: Double }
public struct LayoutRect: Sendable, Hashable { x, y, width, height }
public struct LayoutGraph: Sendable, Equatable { public struct Node { id: Int; width, height: Double }
    public struct Edge { from, to: Int }; nodes: [Node]; edges: [Edge] }
public struct LayoutOptions: Sendable, Equatable { layerGap = 120.0, nodeGap = 40.0, componentGap = 160.0,
    sweeps = 24, placementPasses = 8, targetAspect = 1.6 }
public struct LayoutStats: Sendable, Equatable { components, dummyNodes, crossingsBefore, crossingsAfter, sweepsRun: Int }
public struct LayoutResult: Sendable, Equatable { positions: [Int: LayoutPoint] /* top-left */; ranks: [Int: Int]
    reversedEdges: [Int] /* sorted edge indexes */; selfLoops: [Int]; routes: [Int: [LayoutPoint]] /* bend points */
    bounds: LayoutRect; stats: LayoutStats }
public enum LayeredLayout { public static func layout(_: LayoutGraph, options: LayoutOptions = .init()) -> LayoutResult }
```

The internal stages are tested with `@testable`:
- `CycleBreaker.reversedEdges`
- `Layering.longestPath`
- `Dummies.insert`
- `CrossingReduction.sweep` and `.crossings` (BJM)
- `Placement.isotonic(desired:extents:gap:)` (PAV)
- `ComponentPacking.pack`

**Shared test helpers:** `SplitMix64` and `randomGraph(seed:n:e:)`, with widths of 160 to 260 and heights of 60 to 300.

| Task | Stage | Golden or property test, its exact assertion, and the mutation |
|---|---|---|
| L1 | Types, self-loops, cycle breaking | **G3** `twoCycleReversesTheHigherEdge`. Edges `[0→1, 1→0]` give `reversedEdges == [1]`. Mutation: tie to the highest id. **G4** `selfLoopsAreSetAside`. Edges `[0→0, 0→1]` give `selfLoops == [0]`, `ranks == [0:0, 1:1]` and no reversed edges. Mutation: feed self-loops to layering, which never terminates or reverses one. **P3** `reversingTheReversedSetLeavesADAG` (Kahn over 200 seeds). Mutation: reverse nothing. |
| L2 | Layering and dummies | **G1** `chainGoesLeftToRight`. Edges `0→1→2` give `positions == [0:(0,0), 1:(320,0), 2:(640,0)]`. Mutation: rank by in-degree from the sinks, which mirrors it. **G6** `aLongEdgeGetsOneDummy`. Edges `0→1, 1→2, 0→2` give `stats.dummyNodes == 1` and `routes[2]!.count == 1`, with `routes[2]![0].x` in `[320, 520]` and outside node 1's rect. Mutation: skip the dummies. **P6** `routesHaveOnePointPerSpannedGap`. `routes[i].count == abs(rank(to) − rank(from)) − 1`. |
| L3 | Crossing reduction | **G5** `barycenterUncrossesTheSecondLayer`. Edges `0→3, 1→2, 0→2` give `crossingsBefore == 1`, `crossingsAfter == 0` and `positions[3]!.y < positions[2]!.y`. Mutation: zero sweeps. **P5** `crossingsNeverIncrease`. `crossingsAfter <= crossingsBefore`; keep the best order, not the last. Mutation: keep the last sweep. `bjmMatchesBruteForce`. The BJM count equals an O(E²) count on 200 random bipartite layers. Mutation: an off-by-one in the accumulator tree. |
| L4 | Placement and coordinates | **G2** `diamondIsBalanced`. Edges `0→1, 0→2, 1→3, 2→3` give `positions == [0:(0,70), 1:(320,0), 2:(320,140), 3:(640,70)]`, derived by hand from D17's alternating PAV sweeps toward the neighbour-centre mean and normalised so the smallest y is 0. Mutation: clamp instead of pooling. `isotonicPoolsViolators`. Desired `[0, 0]` and extents `[100, 100]` with gap 40 give `[-70, 70]`. **P1** `noTwoNodesOverlap` (200 seeds). Rects grown by `nodeGap/2 − 1e-9` are pairwise disjoint. Mutation: drop the gap constraint. **P2** `edgesAreRankOrdered`. For each edge not a self-loop, oriented through `reversedEdges`: `x(to) >= x(from) + width(from) + layerGap − 1e-9`. Mutation: x from the order index, not the rank. |
| L5 | Components, determinism and scale | **G7** `componentsArePackedApart`. Edges `0→1, 2→3` and an isolated node 4 give `stats.components == 3`, pairwise disjoint component boxes, and `positions[0] == (0,0)` (largest first, then lowest id). Mutation: lay out as one graph, which puts 4 in rank 0 beside 0. **P4** `permutingTheInputChangesNothing`. Shuffling `nodes` and `edges` (edge indexes remapped) gives an identical `LayoutResult`. Mutation: drop the internal sort. `runningTwiceIsIdentical`. `fiveHundredTablesStayBounded`. `randomGraph(seed: 42, n: 500, e: 1000)` gives `stats.dummyNodes <= 20_000`, `sweepsRun <= 24` and `positions.count == 500`. The opt-in `SIFT_RUN_LAYOUT_BENCH=1` prints the release time and expects under 250 ms. |
| L6 | Route points and bounds | `boundsEncloseEveryNodeAndRoute`. `selfLoopsHaveNoRoute`. |

**Commands:** `swift test --no-parallel --filter SiftLayoutTests`. Use one commit per task, for example "Break cycles and set self-loops aside", "Rank by foreign-key direction with dummy nodes", "Reduce crossings with barycenter sweeps", "Place nodes with isotonic sweeps", "Pack components and prove determinism", "Report routes and bounds".

## 13. Review focus: the five likeliest failure modes

1. **A secret leaks.**
   - Check every path a password can take: `PGConnectionParameters.description`, any `PGError` message built from parameters, `print` or `debugPrint` of a `DiscoveredDatabase` in code or in a test's `#expect` message, accessibility labels, the JSON in `connections.json` and the map files, and Swift Testing's failure output (it prints compared values).
   - `Secret` must stay non-`Codable`, with a masked mirror.
   - Container passwords must never reach disk.
2. **Read-only is not enforced, or identifiers are injectable.**
   - Check that D5's post-connect `SHOW` check exists and fails closed.
   - Check that the writable connection exists only in `PGFixture`.
   - Check that every relation name in SQL goes through `PGIdentifier.qualified`. The fixture's `Weird "Name"` table must be exercised by the count and the preview.
   - Check that the exact count uses `BEGIN READ ONLY` and always ends the transaction.
3. **Catalog edge cases and identity.**
   - Partition FK clones (`conparentid = 0`), dropped columns, PK and FK column order (`ordinality`, not `attnum`), expression index columns, `reltuples = -1`, hidden partitions, and FKs into filtered or unprivileged schemas, which make dangling map edges.
   - **Anything keyed by OID**: selection, pins, card ids and FK navigation. It breaks silently after a container is recreated (D7).
4. **Tests that lie.**
   - **Layout nondeterminism:** a `for` over a `Dictionary` or `Set`, or a sort without a total order, can turn the goldens flaky across processes (hash seeding).
   - **Vacuous cost pins:** a pin can pass because nothing is visible, because culling hid the work, because tile extents are over the 2^20 overscan limit (so pans silently re-rasterize and someone loosens the pin), or because a drag writes unobserved state and frames are skipped (FP-U).
   - Every pin asserts its precondition, and every test has its mutation run once.
5. **Cross-platform plumbing.**
   - The Windows build of a MetalUI consumer with the SDL and AccessKit traits (never done before), with three flag sources concatenated.
   - The Linux SDL cache and `ldconfig`, and fonts for headless tests (D3).
   - The unix socket path length (macOS 104) for the fake daemon.
   - Named-pipe timeouts.
   - `../MetalUI` drifting between a developer's checkout and the pinned `METALUI_REF`.
   - `--no-parallel` being forgotten in a new CI step.
